# Правила работы над проектом

Договорённости, обязательные для любой правки кода dev-tool. Документ читается
до начала работы.

---

## 1. Простота как требование

Приоритет проекта — читаемость и предсказуемость кода, а не его выразительность.

- обычные функции, циклы и условия вместо абстракций, фабрик и метаклассов;
- комментарии на русском, объясняющие **почему** сделано так: какой сценарий
  ломается при другом решении. Комментарий, пересказывающий код, не нужен;
- новые зависимости не добавляются без явной необходимости. Текущий набор —
  семь пакетов на бэкенде и два на фронте;
- три понятные строки предпочтительнее одной сложной;
- слои «на будущее» не создаются: абстракция с единственной реализацией
  избыточна.

Если простое решение неприменимо, причина фиксируется комментарием рядом с кодом.

## 2. Границы модуля

**1 модуль = 1 роутер на бэкенде = 1 вкладка во фронте.** Модули независимы и
не импортируют друг друга.

- добавление модуля не требует правок в других модулях;
- подключение — одна строка в `backend/main.py` и одна в
  `frontend/src/modules/registry.js`;
- общий код живёт в `backend/access.py`, `backend/logging_setup.py`,
  `backend/share.py` и `frontend/src/shared/`. Код, нужный одному модулю, в
  общие файлы не выносится;
- зафиксированное исключение: параметры хранилища (`STORAGE_BACKEND`, `PG_*`)
  читаются в `modules/silences/config.py`, оттуда их берут `share.py` и модуль
  alerts. Отдельного конфига хранилища в проекте нет.

Пошаговая инструкция — [MODULES.md](MODULES.md).

## 3. Зона ответственности

Модуль **alerts** (`backend/modules/alerts/`, `frontend/src/modules/alerts/`,
пути `/alerts/` и `/webhook/`) имеет отдельного владельца. Его файлы, роуты и
переменные окружения не изменяются в рамках задач по другим модулям. Чтение кода
для понимания общей картины допустимо.

Необходимость правки в чужом модуле фиксируется описанием проблемы; решение
принимает владелец модуля.

## 4. Совместимость и версии

| Что | Версия | Где закреплено |
| --- | --- | --- |
| Python | 3.12-slim | `backend/Dockerfile` |
| Node (сборка фронта) | 20-alpine | `frontend/Dockerfile` |
| Vue | 3, Composition API, `<script setup>` | без TypeScript и сторонних UI-библиотек |
| Стили | CSS в `<style scoped>` + переменные темы | без препроцессоров и utility-фреймворков |

Зависимости бэкенда закреплены диапазоном «от рабочей версии до следующего
мажора» (`fastapi>=0.128,<1.0`): патчи и минорные версии приезжают, ломающий
мажор — нет. Новые зависимости добавляются тем же способом, с комментарием о
назначении.

**Минимальная версия Python — 3.10.** Раньше код держали совместимым с 3.9
(`list[str]` в аннотациях допустим с 3.9, `str | None` — только вместе с
`from __future__ import annotations`), но модуль alerts использует `str | None`
в полях pydantic-моделей, а их pydantic вычисляет в рантайме — на 3.9
приложение не стартует вовсе. Образ собирается на 3.12, так что на выкат это не
влияет; учитывать нужно при локальном запуске на системном интерпретаторе.

## 5. Конфигурация — только через окружение

Различия между стендами выражаются переменными окружения, которые модуль читает
в своём `config.py` при импорте. Код под конкретный стенд не правится.

- набор окружений задаётся **префиксом имени переменной**, а не её значением:
  `alert_<env>`, `rules_<env>`, `vm_<env>`, `vmagent_<env>`, `vmalert_<env>`,
  `access_<module>`. Добавление окружения не требует релиза;
- несколько нод одного компонента (HA) перечисляются **через запятую**;
- имена переменных — только `[A-Za-z0-9_]`: имя с дефисом docker отбрасывает;
- **каждая новая переменная описывается в [`.env.example`](../.env.example)** —
  в своём блоке, с комментарием и примером значения. Этот файл выполняет роль
  справочника по конфигурации.

## 6. Ошибки и отказы

- недоступный внешний сервис — понятный **502** с текстом, не стектрейс
  (обработчики `AlertmanagerError`, `VictoriaError`, `AlertsN8nError` в `main.py`);
- отсутствие доступа к модулю — **403** из `require_module(...)`;
- отказ одного из параллельных запросов не отменяет остальные: используется
  `Promise.allSettled`, ошибка показывается рядом с соответствующим запросом
  (пример — `QueryPanel.settle()`);
- отмена запроса пользователем (`AbortError`) ошибкой не считается;
- деградация предпочтительнее отказа: без Postgres модуль alerts работает без
  истории; при недоступном `/access/me` фронт показывает все вкладки, а API
  по-прежнему отвечает 403.

## 7. Производительность

Интерфейс сравнивается пользователем с родными vmui и вебом Prometheus, поэтому:

- крупные ответы внешних систем передаются **сырыми байтами** (`Response`), без
  разбора и пересборки JSON;
- используется один общий `httpx`-клиент на процесс (keep-alive) с
  `trust_env=False`, чтобы запросы к внутренним адресам не уходили в
  корпоративный прокси;
- в памяти кэшируется только то, что меняется редко (targets, tsdb, имена
  метрик, rules); живые данные (`query`, `query_range`, `alerts`) не кэшируются;
- на фронте действуют лимиты отрисовки, а кнопка «Показать ещё» дорисовывает из
  **уже полученного** ответа, без повторного запроса к источнику;
- на время загрузки показываются скелет-плашки (`shared/Skeleton.vue`).

## 8. Проверки

Бэкенд:

```bash
cd backend && python -m unittest discover tests
```

Внешние сервисы в тестах не поднимаются, их вызовы подменяются. Переменные
окружения задаются **до** импорта модулей приложения: `config.py` читает
окружение при импорте. Тестами покрывается то, что ломается незаметно: разбор
конфигурации, параллельность, обработка ошибок, короткие ссылки.

Фронтенд:

```bash
cd frontend && npm ci && npm run build
```

## 9. Чек-лист перед сдачей

- [ ] новые переменные окружения описаны в `.env.example`;
- [ ] новый модуль добавлен в `KNOWN_MODULES` (`backend/access.py`) и в
      `registry.js` — иначе вкладка не появится при включённом RBAC;
- [ ] новый путь API добавлен и в `frontend/nginx.conf`, и в `vite.config.js` —
      иначе он работает только в одном из режимов;
- [ ] `npm run build` и `python -m unittest discover tests` проходят;
- [ ] затронутые документы в `docs/` обновлены;
- [ ] секретов в коде и в репозитории нет.

## 10. Запрещённые изменения

- правка чужого модуля вне поставленной задачи;
- ввод TypeScript, state-manager, UI-кита, CSS-препроцессора;
- права тоньше уровня модуля (RBAC на окружение) — решение принято сознательно;
- логирование каждого успешного запроса, а также значений cookie и токенов —
  в лог идут только размеры, см. [LOGGING.md](LOGGING.md);
- адреса стендов, записанные в коде.
