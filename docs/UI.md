# Интерфейс: шрифты, палитра, компоненты

Единый визуальный язык описан здесь и реализован в
`frontend/src/shared/theme.css`. Новый экран собирается из готовых классов и
переменных: собственные цвета, размеры и шрифты в компонентах не задаются.

---

## Шрифты

Подключаются в `frontend/index.html` через Google Fonts, объявляются
переменными в `theme.css`. Три гарнитуры, у каждой своя роль:

| Переменная | Гарнитура | Где применяется |
| --- | --- | --- |
| `--display` | **Space Grotesk** (500/600/700) | заголовки: `h1`–`h3`, `.card-title`, `.tab-title`, `.head-title`, `.brand-name` |
| `--sans` | **Manrope** (400/500/600/700) | весь основной текст, кнопки, подписи полей |
| `--mono` | **JetBrains Mono** (400/500) | всё техническое: значения полей ввода, метрики, запросы, лейблы, времена, идентификаторы |

```css
--display: "Space Grotesk", "Manrope", -apple-system, sans-serif;
--sans:    "Manrope", -apple-system, BlinkMacSystemFont, "Segoe UI", Roboto, sans-serif;
--mono:    "JetBrains Mono", ui-monospace, SFMono-Regular, Menlo, Consolas, monospace;
```

Правила:

- базовый размер — 14 px, вспомогательные подписи 12 px, мелкие пометки 11 px;
- заголовки идут с `letter-spacing: -0.015em` — это задано глобально;
- **всё, что копируют или сравнивают глазами, набирается `--mono`**: имена
  метрик, PromQL, лейблы, идентификаторы, даты и длительности. Моноширинный
  шрифт выравнивает цифры по колонкам и делает разницу заметной;
- `input`, `textarea`, `select` уже используют `--mono` глобально;
- новые гарнитуры не добавляются.

## Палитра

Цвета берутся **только** из переменных — ни одного литерального цвета в
компонентах, кроме палитры серий графика.

| Переменная | Назначение |
| --- | --- |
| `--bg`, `--bg-rail` | фон страницы и левого рельса |
| `--panel`, `--panel-2` | карточки и вложенные поверхности (поля ввода, выпадающие списки) |
| `--border`, `--border-soft` | обычная и приглушённая рамка |
| `--text`, `--text-dim`, `--text-mute` | основной, вторичный и служебный текст |
| `--accent`, `--accent-bright`, `--accent-soft` | акцент вкладки: активные элементы, фокус, подсветка |
| `--danger` | ошибки и деструктивные действия |
| `--info`, `--info-soft` | вторая смысловая категория |
| `--chip`, `--track` | фон бейджей и полос-дорожек |
| `--shadow`, `--shadow-pop` | тени карточек и всплывающих элементов |

Тёмная тема — база (Dracula), светлая включается атрибутом
`data-theme="light"` на `<html>` и переопределяет те же переменные.
`color-scheme` выставлен, поэтому нативные элементы — календарь `datetime-local`
и полосы прокрутки — окрашиваются в тон теме.

Выбор темы хранится в `localStorage`, переключатель находится в левом рельсе.

## Цвет-пространство вкладки

Активная вкладка задаёт `data-space` на `<html>`, и палитра перекрашивается
целиком: модуль воспринимается как отдельное место, а не как ещё одна страница.

```css
:root[data-theme="dark"][data-space="victoria"]  { --accent: #ff7a59; … }
:root[data-theme="light"][data-space="victoria"] { --accent: #d1502f; … }
```

- **тема указывается явно.** Без `data-theme` тёмный набор протечёт в светлую
  тему;
- переопределяются те же имена переменных — новые не вводятся;
- ширина рабочей области тоже относится к пространству:

```css
html[data-space="victoria"] .content { max-width: min(1840px, 96vw); }
html[data-space="alerts"]   .content { max-width: min(1320px, 96vw); }
```

Модулю с плотными таблицами нужна широкая область, форме — узкая. По умолчанию
действует стандартная ширина.

Добавление пространства новому модулю — один блок переменных в `theme.css`.
В JavaScript при этом ничего не меняется.

## Готовые классы

| Класс | Назначение |
| --- | --- |
| `.card`, `.card-head`, `.card-title`, `.card-hint` | карточка-секция; заголовок отмечен акцентной чёрточкой |
| `.field`, `.input`, `.req`, `.grid-2` | поля ввода, метка обязательности, двухколоночная сетка |
| `.btn`, `.btn-primary`, `.btn-ghost`, `.btn-icon`, `.btn-sm` | кнопки |
| `.msg`, `.msg-ok`, `.msg-err` | сообщения об успехе и ошибке |
| `.endpoint` | технический адрес или идентификатор моноширинным |

Геометрия единообразна: радиус 12 px у карточек, 7 px у полей и кнопок, 6 px у
мелких элементов. Отступ внутри карточки — 18–20 px, между карточками — 16 px.
Наведение и фокус меняются плавно (`transition` 0.15 s); фокус поля — акцентная
рамка плюс мягкое кольцо `box-shadow`.

Компоненты общего назначения лежат в `frontend/src/shared/`:
`Skeleton.vue` (плашки на время загрузки), `api.js` (http-клиент), `time.js`
(показ дат в заданной таймзоне), `urlstate.js` (состояние вида в URL).

## Поведение интерфейса

Требования, которые распространяются на все модули.

**Ожидание.** Первая загрузка — скелет-плашки, а не пустой экран. При повторном
запросе прежние данные остаются на месте и приглушаются классом `dim`: экран не
дёргается, но видно, что идёт обновление.

**Объём.** На отрисовку действуют лимиты (строк в таблице, линий на графике,
элементов в автодополнении). Сверх лимита показывается кнопка «Показать ещё»,
которая дорисовывает следующую порцию **из уже полученного ответа**, не обращаясь
к источнику повторно.

**Поиск и раскрытие.** Найденное раскрывается автоматически, но явное действие
пользователя всегда сильнее автоматики: закрытую вручную группу поиск не
раскрывает обратно. Новый поисковый запрос сбрасывает ручные закрытия.

**Копирование.** Текст, который переносят в запрос, отрисовывается в готовом
виде: `key="value"` без пробелов вокруг `=`. Выделил — вставил, править не
требуется. Рядом с составными значениями уместна кнопка копирования целиком.

**Ошибки.** Ошибка одного запроса не прячет результаты остальных: она
показывается отдельным блоком `.msg-err` с номером запроса, к которому
относится.

**Клавиатура.** `Enter` выполняет действие формы, `Shift+Enter` переносит
строку, `Escape` закрывает выпадающие элементы и открепляет всплывающие окна,
стрелки двигают выбор в списках подсказок.

**Ссылка на вид.** Состояние экрана живёт в query-параметрах URL и обновляется
через `history.replaceState`. Любой вид можно передать ссылкой; кнопка в шапке
укорачивает её через `POST /share`.

**Тексты.** Интерфейс на русском. Технические названия, пришедшие из внешних
систем (Graph, Targets, Rules, TSDB Status), сохраняются как есть — они совпадают
с родными интерфейсами Prometheus и vmui, и перевод только запутает.

## Что не используется

- CSS-препроцессоры и utility-фреймворки;
- сторонние библиотеки компонентов и иконочные шрифты — иконки задаются атрибутом
  `d` инлайнового `<svg>` в дескрипторе модуля;
- глобальные стили за пределами `theme.css`: остальное живёт в `<style scoped>`;
- литеральные цвета и размеры шрифта в компонентах вместо переменных.
