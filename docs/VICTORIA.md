# Модуль victoria

Тонкий прокси к кластерам VictoriaMetrics. Фронт запрашивает данные у бэкенда,
бэкенд обращается к нужному компоненту кластера и возвращает его ответ. API
vmselect совместим с Prometheus, поэтому на фронте разбирается обычный
Prometheus-формат.

---

## Конфигурация

Кластер описывается переменными окружения; имя `<env>` после префикса становится
названием вкладки (приводится к нижнему регистру).

| Переменная | Обязательна | Что включает |
| --- | :---: | --- |
| `vm_<env>` | да | vmselect → **Graph** и **TSDB Status** |
| `vmagent_<env>` | нет | vmagent → **Targets** |
| `vmalert_<env>` | нет | vmalert → **Rules** |

`vm_<env>` — Prometheus-совместимый адрес, обычно оканчивается на
`/select/<accountID>/prometheus`. Несколько нод (HA) перечисляются через
запятую, чтение идёт с первой живой. Кластер только под хранение описывается
одной переменной `vm_<env>` — под-вкладок Targets и Rules у него не появится.

Разбор префиксов учитывает, что `vm_` не пересекается с `vmagent_`/`vmalert_`:
после `vm` символ `_` идёт только у vmselect.

### Мультитенантность

Данные в разных тенантах описываются полным путём на каждый тенант, подпись
задаётся двойным подчёркиванием:

```bash
vm_prod__platform=http://vmselect:8481/select/0/prometheus
vm_prod__billing=http://vmselect:8481/select/5:2/prometheus
```

Кластер становится **одной вкладкой с селектором тенанта**. Тенант влияет только
на чтение метрик (Graph и TSDB Status); `vmagent_`/`vmalert_` общие на кластер.
Разделитель — именно двойное `__`, деление идёт по первому вхождению, поэтому
`vm_prod__team_a` читается как кластер `prod`, тенант `team_a`.

Если кластер объявлен и простым, и с тенантами, приложение оставляет
мультитенантный вариант и пишет предупреждение в лог.

## Роуты

| Под-вкладка | Компонент | Роут бэкенда → API VM |
| --- | --- | --- |
| Graph | `QueryPanel.vue` | `/{env}/query`, `/{env}/query_range`, `/{env}/labels`, `/{env}/label_values` |
| Targets | `TargetsList.vue` | `/{env}/targets` → vmagent `/api/v1/targets` |
| Rules | `RulesAlerts.vue` | `/{env}/rules`, `/{env}/alerts` → vmalert |
| TSDB Status | `Cardinality.vue` | `/{env}/tsdb` → vmselect `/api/v1/status/tsdb` |
| Disk Usage | `DiskUsage.vue` | `/disk-usage` — сводно по всем кластерам |

`GET /victoria/environments` отдаёт список кластеров с флагами доступных
под-вкладок и подписями тенантов. Фронт строит по нему вкладки.

Названия под-вкладок взяты из веба Prometheus и намеренно не переводятся.
**Disk Usage** — собственная, считается по всем кластерам сразу и от выбранного
не зависит.

## Скорость

Модуль сравнивается пользователем с родными vmui и вебом Prometheus, у которых
нет промежуточных хопов. Неустранимый overhead — цепочка
nginx → oauth2-proxy → бэкенд; остальное оптимизировано:

- ответы VM проходят через бэкенд **сырыми байтами** (`Response`): JSON не
  разбирается и не пересобирается — на мегабайтных ответах это экономит сотни
  миллисекунд CPU на запрос;
- `query` и `query_range` не кэшируются — их ускоряет собственный rollup-кэш VM,
  и заслонять его не нужно;
- один общий httpx-клиент на процесс (keep-alive). Connect-таймаут 3 секунды:
  мёртвая HA-нода не подвешивает запрос, происходит быстрый переход к следующей.
  Read-таймаут — 30 секунд;
- кэш в памяти: targets и `/status/tsdb` — 5 минут, имена метрик и лейблов — 5
  минут, rules — 1 минута. Кнопки «Обновить» шлют `refresh=1` и читают мимо кэша;
- у vmagent запрашивается `state=active` — dropped-цели не сериализуются вовсе;
  из активных выбрасывается `discoveredLabels`, который весит больше остального;
- в TSDB Status топ метрик сверяется одним instant-запросом
  `count({__name__=~…}) by (__name__)`: показываются только метрики, реально
  лежащие в тенанте сейчас, — в `/status/tsdb` попадают и уже исчезнувшие серии;
- под-вкладки обёрнуты в `KeepAlive`: переключение не пересоздаёт компонент и не
  перечитывает данные. Смена кластера или тенанта пересоздаёт (через `:key`);
- в Targets все группы по умолчанию свёрнуты — тысячи строк тормозили DOM;
  поисковая строка каждой цели предвычисляется один раз при загрузке.

## Вкладка Graph

Несколько выражений PromQL/MetricsQL в одной панели (аналог Add Query в vmui):
серии всех запросов рисуются на одном графике, снизу легенда с бейджами q1/q2.
Режимы — **Graph** (range → uPlot), **Table** (instant) и **JSON**. `Enter`
выполняет запрос. Ошибка одного выражения не прячет результаты остальных.

Лимиты отрисовки: таблица ≤ 1000 строк, график ≤ 20 линий, автодополнение
≤ 10000 имён. Сверх лимита — кнопка «Показать ещё», дорисовывающая следующую
порцию из уже полученного ответа.

### Ось времени и разрывы данных

Требование: **график обязан показывать, что метрика перестала приходить.**

- ось X строится как ровная сетка на **весь запрошенный период** `start…end`, а
  не по крайним точкам ответа. Иначе ось сжимается до последней точки, линия
  дотягивается до правого края, и запрос за неделю выглядит так, будто данные
  идут до сих пор;
- точка ответа кладётся в **ближайший слот сетки**: VM выравнивает метки времени
  по своей сетке, кратной шагу, и сравнение «в лоб» их не находит;
- шаг сетки — запрошенный `step`, но если VM вернула точки реже (округлила шаг
  вверх), берётся её шаг: иначе половина слотов осталась бы пустой и сплошная
  линия распалась бы на пунктир;
- слот, в который ничего не легло, остаётся `null`, а серии рисуются с
  `spanGaps: false` — **разрыв данных виден как разрыв линии**;
- серия, у которой данные оборвались раньше конца окна, помечается в легенде
  временем последней точки: значение рядом с ней старое, и это сказано явно;
- под графиком выводится показанный период и шаг.

Подписи оси: дата ставится у первой метки и там, где начинаются новые сутки,
внутри суток остаётся только время. Ровная полночь читается как дата, время у
неё не дублируется.

### Тултип

По наведению показывается ближайшая **линия**: цвет, полное имя с лейблами,
значение и время.

- расстояние меряется до самой линии — до отрезков рядом с курсором, а не по
  вертикали в точке. На крутом участке вертикаль уводила выбор на соседнюю серию;
- серии, скрытые в легенде, не участвуют: их линии на графике нет;
- если курсор дальше 26 px от любой линии, окошко не показывается — пустое место
  графика ничего не выбирает;
- клик закрепляет окошко: оно перестаёт следовать за курсором, лейблы можно
  выделить и скопировать. Каждая строка отрисована как готовый кусок запроса
  `key="value"` без пробелов вокруг `=`. Кнопка ⧉ копирует серию целиком,
  `×` и `Escape` — открепляют.

### Прочее в Graph

- **История запусков** — 10 последних запусков в `localStorage` (`vm.qhistory`),
  общая на все кластеры. Запись — весь запуск целиком, поэтому клик восстанавливает
  все поля ровно как было и сразу выполняет запрос;
- **выделение мышью по графику** задаёт диапазон: подставляется в «От»/«До» и
  перезапрашивается, чтобы шаг пересчитался под новое окно;
- **таблица** по высоте не режется, страница листается целиком. Горизонтальный
  ползунок один — прилипший к нижнему краю экрана, синхронизированный с таблицей
  «в долях», а не копированием `scrollLeft`. Ширина колонки тянется мышью за
  правый край заголовка, двойной клик сбрасывает.

## Остальные вкладки

**Targets** — цели сгруппированы по job (scrapePool), в шапке группы `up/total`.

**Rules** — правила vmalert; каждое раскрывается (expr, labels, annotations,
health, активные алерты). Фильтр-пилюли по состоянию и поиск по имени, выражению
и лейблам. Найденное раскрывается автоматически, пока таких правил не больше 50.

**TSDB Status** — кардинальность: топ метрик и лейблов по числу серий.
«Показать ещё» поднимает topN и перечитывает статус.

**Disk Usage** — заполненность дисков по всем кластерам, по строке на каждую
группу vmstorage (лейбл `group`): занято, свободно, процент из
`sum by(group) (vm_data_size_bytes | vm_free_disk_space_bytes)` и прогноз
заполнения по скорости роста. Кластеры без метрик бэкенд помечает полем `error`,
но фронт такие строки не показывает: вкладка отвечает на вопрос «где сколько
занято», сообщение «в кластере X нет метрик» здесь лишний шум. Метрики без
лейбла `group` попадают в группу «—».
